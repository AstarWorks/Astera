# Area: modes, combat, weapons

Owner track `wp/modes-combat`. Seed: audit 2026-10-26. Items: Board prefix `MODE-`.

## 構想 (source)
- Siege PvP with gun / sword / magic roles, 15-30 min matches (`docs/game-design/vision.md`, `pillars.md`).
- **Norma is part of every mode** (founder 2026-10-26, ADR-0268: shared layer `content/norma-layer/layer.yaml`, `norma_win` per mode, the old `norma` mode is now `skirmish`): stars pop from generators, a kill bursts carried stars, per-level STAR or KILL goal, 100% Orange Juice style; highest Norma level wins (ADR-0271, `docs/game-design/stars-and-norma.md`).
- Weapons RTM-style MAIN+SUB caps; the 2-weapon cap is kept; starter kit includes a gun.
- Matches target siege-scale maps; keep a small debug arena for e2e.
- Playable loop: queue, form, countdown, ACTIVE, fight, respawn, objective, end summary + rewards, lobby (`docs/game-design/playable-loop-checklist.md`).

## 現状
- 9 mode files in `content/game-modes/` (skirmish, annihilation, break-core, carry-tnt, carry-mini-tnt, capture-wool, steal-jewelry, battle-loyal, pve-waves); 9 queue lanes in `content/matchmaking/queue.yaml`, one per mode (`carry-mini-tnt` got its lane in MODE-05; the Play menu and lobby pads list lanes from this file, so no code change). `ShippedMatchContentDecodesTest` fails if a mode has no lane.
- Play gate mode picker with "vs bots" tile per lane (ADR-0248). Bots: A* pathing, star/generator objectives, retreat, Norma goal choice (`tools/bot-runner`).
- Leaving a running match (MODE-14): a dropped connection holds the seat for a 60 s rejoin window, then forfeits; a deliberate leave (`/astera travel lobby`, F-menu Leave) forfeits at once (stars burst, seat released, inventory + lobby kit restored, loss recorded). carry-mini-tnt is a real objective (CarryMiniTntGameMode, MODE-05) built on the RTM concept "collect 10 mini-TNTs into 1 larger TNT" (`docs/adr/0029-rtm-empirical-catalog.md:80`): pieces from the pickup spots (carry up to 4) are banked at the team's OWN base into a pool; at `minis_per_tnt` (10) they combine into one real TNT at `tnt-spawn` (presentation moment `mini-tnt-combined`, pool progress on the sidebar), which only that team can pick up and which wins (`tnts_to_win` 1) when delivered to the enemy base, using the same carry rules as carry-tnt (`TntCarrier`). The own-base banking route and the one-TNT-at-a-time rule are our choices; the docs give only the 10-into-1 idea.
- Real-server playthrough e2e for every mode (`*PlaythroughE2eTest`: norma, annihilation, break-core, pve-waves, carry-tnt, carry-mini-tnt, capture-wool, steal-jewelry, battle-loyal). The objective-mode ones share `ObjectivePlaythroughBase.finishMatch`, which asserts the end screen, the VICTORY/DEFEAT verdict each player is told and that sound packets reached the client (the client bot records no title packets, so the verdict is read from chat).
- Siege-isles on foot: `SiegeCrossingPlaythroughE2eTest` (window profile, not in the skip list) queues break-core, has the red bot walk with the A* `ObjectiveWalker` red island -> bridge -> centre island -> bridge -> the front of the blue core (no teleports), asserts the cores + Norma level/goal lines on the sidebar, breaks the core, and checks the VICTORY/DEFEAT verdict via `finishMatch`. `SiegePlaythroughE2eTest` keeps the build / core-rule / void checks with teleports, and game-sim `SiegeModesScenarioTest` covers the rules of all five siege modes. Gap: the e2e image swaps in the compact debug stage (`docker/e2e-tune-content.sh`), so the production-size islands, outpost towers and walls are never walked by a bot in CI; the route graph there is only the authored island/bridge list.
- ~90 items, 85 skills, ~30 real weapons (guns: pistol, rifle, shotgun, sigil-rifle, vendetta-rifle; swords; 5 staves); demo items (`rtm-blaster`, `simple-shoot`, `vfx-demo-*`, `anim-demo-*`) live in production content.
- Demo/dev items are flagged `astera:demo: "true"` (ADR-0270) and stay usable by id but out of admin catalogs, kits and racks (`DemoContentHiddenScenarioTest`); they were deliberately not moved to a separate content path because game-sim/VFX scenarios load them by id from `content/`. The TTK table is `docs/game-design/weapons/ttk.md` (generated by `scripts/ttk-table.py`, bands guarded by `ShippedWeaponTtkBandsTest`).
- `weapon_limits: "gun:1,sword:1,staff:1,total:2"` enforced by `MatchWeaponLimitListener`, now a default of the Norma layer (`content/norma-layer/layer.yaml`) so every mode keeps the 2-weapon cap (a mode may override or blank it). Covered by game-sim `WeaponLimitScenarioTest` (skirmish + carry-tnt).
- The Norma sidebar goal (`Norma Lv n/5`, `Goal: Stars|Kills x/y`) is live for all modes; `NormaPlaythroughE2eTest` now asserts both lines.
- Norma/stars: generators pop stars, kill bursts stars, level via STAR or KILL goal, `PaperNormaPresentation`; stars cannot yet be spent (items/ultimates not built).
- Combat: resource pools, melee, mob damage, 15 statuses, element matrix.
- Stage allocation (MODE-06): a stage id is one fixed set of coordinates in the `arenas` world and hosts one match at a time (`MatchFoundUseCase.isStageBusy`). World slots / `ArenaPaster` (ADR-0255) are design only, with no code yet, so instancing does not exist. Each siege-family lane therefore has its own copy of the stage: `siege-isles` (break-core) and `siege-isles-{tnt,wool,jewelry,loyal,mini-tnt}`, each shifted +800 on z (stages 800 apart, the ADR-0255 region-independence distance), with their own star generators `siege-<variant>-{north,south,center-east,center-west}`. The six siege lanes now run concurrently. When ADR-0255 slots land, delete the variants and point the lanes back at `siege-isles`. Costs: six large stages to build at boot and in the arena marker; keep the copies in sync when editing `siege-isles.yaml`.

## 理想形
Play shows Norma-based modes and PvE first; siege variants sit in an "advanced" group until each has a real-server playthrough. Every mode carries the Norma layer. A newcomer gets gun, sword and staff access in the first match within the 2-weapon cap, and the sidebar always shows the goal ("Lv n/5, X stars or Y kills to go"). Stars are an in-match resource only (never a currency; ADR-0271), and no star-spending item exists yet; any in-match sink is a later decision. Weapons are ordered by difficulty with a documented TTK table; demo content is split from production.
