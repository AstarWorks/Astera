## Root causes

### Harness bugs (fixed, assertions kept)

1. **Bots were kicked with `invalid_player_movement` on the first position packet.** Since 26.x the server kicks a client that sends a
   second `ServerboundMovePlayer*` before a `ServerboundClientTickEnd` (`ServerGamePacketListenerImpl.receivedPositionThisTick`,
   reset only in `handleClientTickEnd`). `Bot.nudge()` sent bare move packets. Every playthrough (norma, annihilation, break-core,
   game-loop) lost its bots seconds after the queue and cascaded into "never ACTIVE" / "no kill" / "not back in the lobby" rows.
   Fix: `nudge()` ends the tick before and after the move. Also: the bot now applies `PositionElement` relative flags before it
   echoes `ServerboundAcceptTeleportation`.
2. **Astera deaths never raise a vanilla death** (ADR-0149: the Bukkit health mirror is held above zero), so
   `ClientboundPlayerCombatKill` never arrives and every "kill detected" check timed out after 90 shots. The visible death is the death
   cam (spectator game mode). `Bot` now records a death on the spectator game-mode change. Out-of-match deaths (weapon suites) are
   evidenced by the "You were defeated" notice, because the victim is back in the lobby at full HP before any poll can see the dip.
3. **Forced kills used `/damage ... minecraft:player_attack by <bot>`.** `VanillaMeleeSuppressor` cancels vanilla melee from a
   player holding an Astera item, so the command was a no-op. Switched to `minecraft:magic`.
4. **Single-player queues.** After `ff67e15f` a PvP lane never starts solo; `HudE2eTest` (match tab list) queued one bot. It brings a
   partner now.
5. **Weapons suite:** melee sent only the swing, a real client also sends the attack on the entity in the crosshair (as
   `PersonaWeaponsE2eTest` already did); the target was not healed between melee clicks (bleed killed it, sending both bots to the
   lobby where damage is off); staging gave up after 6 attempts; a lethal ranged hit was counted as a miss.
6. **Annihilation:** the pistol magazine (12) ran dry before tier 3; no reload. Added a reload when the status line says `Ammo 0`.
7. **Join:** the first-join tutorial hint owns the action bar for a few seconds; the HP line is checked over the action-bar history.
8. **Velocity log check:** `Broken pipe` after the backend kicked a bot is a peer-disconnect race ("Exception caught while decoding
   frame" + `NativeIoException`), not a decode failure. Those line pairs are ignored (`scripts/e2e.sh` and `VelocityE2eTest`).

### Product bug (fixed)

- **break-core: breaking your own core removed it for good.** `PaperMatchWorldInputAdapter.onBlockBreak` publishes `BlockBroken`
  at MONITOR, i.e. before the server removes the block. `BreakCoreGameMode.broken` puts the core back synchronously, and then the break
  completed and left air. Symptom: after one own-core break the team has no core (`execute if block -46 -60 0 emerald_block` fails).
  Fix: `BlockBroken` is published one tick later.

## Follow-up: weapons reliability (runs 1-5 of this pass)

Root causes (all verified with the gated `[weapons-debug]` trace, `ASTERA_DEBUG_WEAPONS=1`, set only in `docker/docker-compose.e2e.yml`):

1. **Intermittent Weapons melee / ranged failures: harness, not product.** The overworld arena is a night-time flat world;
   zombies wandered in, hit the bots, killed them (an out-of-match Astera death sends the victim to the lobby, where damage and
   hunger are off) and soaked up the dagger arc (`attack Shooter victim=Zombie`). A click taken while the shooter or target was
   in the lobby/respawning never reached a weapon cast, so no `ResourceSpent`, no food change, no hit. The energy path itself is
   sound: every cast that reached `CastSkillUseCase` logged `spend Energy x8 -> Success` and `EnergyFoodBarListener` mirrored
   it (`energy=92 level=18`, regen resyncs follow), so the `lastLevel` shortcut is not at fault. Fix: `WeaponsE2eTest` turns off
   mob spawning and the day cycle, sets day and clears non-player entities before the run (assertions untouched; peaceful was
   rejected because vanilla refills food there). Also found: a bare arm swing never produces a `LEFT_CLICK`; the melee binding
   fires from the entity-attack packet (`EntityDamageByEntityEvent`), as designed.
2. **"Duplicate PlayerJoinedServer" WARN: dead legacy listener, not a double publish.** `PlayerHandoffService.onJoin`
   (ADR-0187, `PlayerInventoryLifecycleListener` at the Bukkit join event) already restores the inventory and marks the session
   `Lobby` before `BukkitEventAdapter` publishes `PlayerJoinedServer` once. `RestoreInventoryOnPlayerJoinedListener` then always
   saw a live session and skipped, so the restore it guarded was never its job. Removed the listener, its wiring and
   `RestoreInventorySnapshotUseCase` (no other users). The inventory restore on first join is done by the handoff service, as intended.
3. **`content/refinement` WARN: optional content.** `ItemsWiring` now loads refinement profiles only when the directory exists
   and logs one INFO line otherwise (`ContentLoader` still warns for other missing dirs).

Results after the fix (Weapons suite 26/26 PASS in both): run 4 `271 / 277`, run 5 `271 / 277`. The 6 remaining failures are the
PersonaWeapons `vendetta-rifle` (magazine of 2 left after the first shot, so right_click/sneak_right cannot cast) and
`crimson-chain-axe / sneak_left` display-entity rows, unrelated to this item.

## Open / observations (not fixed)

1. (Resolved, see Follow-up) `Weapons` melee clicks (one of three, a different one each run; run 8: dagger #2, greatsword #1; plus one `pistol hits 4/4` miss) occasionally spends no energy for dagger and greatsword (run 7: 2 of 9 clicks; the earlier
   run passed all). Damage lands (lingering bleed), the food bar never moves in the 1.2 s sample window. Suspects:
   `EnergyFoodBarListener.sync` (`lastLevel` shortcut when the level is unchanged, `plugin/core/.../hud/EnergyFoodBarListener.kt`) or a
   cast skipped while the previous cast's cooldown/bleed tick is running. Needs a server-side debug log of `ResourceSpent` per click.
2. `PersonaWeapons`: `bastion-greatsword / right_click`, `verdict-hammer / right_click`, `sigil-rifle / left_click` showed "no damage" in
   run 7. The target path in the notes jumps to the lobby spawn (0, 65, 6) within 0.5 s of the cast and HP is back at 20: lethal hits
   (damage numbers -8 / -16) outside a match. The check now also accepts the "You were defeated" notice as evidence.
3. (Resolved, see Follow-up) Every join logs `WARN RestoreInventoryOnPlayerJoinedListener: Duplicate PlayerJoinedServer ... (state=Lobby)`. The session is already
   `Lobby` when this listener runs (ordering between the session creator and the restore listener, or a double publish in
   `BukkitEventAdapter.kt:157`). Harmless today, but the inventory restore is skipped on every first join; worth confirming that is intended.
4. (Resolved, see Follow-up) Startup `WARN ContentLoader: Content directory not found: /content/refinement` (the e2e image has no `content/refinement`).
5. For first-time players the tutorial hint replaces the HP status line on the action bar for several seconds; the player has no HP
   readout meanwhile (design question, not a defect per se).
