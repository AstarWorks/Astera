# Testing policy

**Founder decision 2026-10-23: unit tests are forbidden. Only integration tests are allowed.**

Unit tests (one class / use case / listener / domain object exercised with fakes, mocks or in-memory stubs) cost more to maintain than they return. Do not write them. Delete them on sight.

## Allowed (integration)

- `tools/game-sim` scenario tests: boot the real wiring and drive it.
- `tools/e2e`: real Paper server plus bots.
- Postgres `*IT` (Testcontainers / real DB) and `MigrationResolutionTest` (real SQL migrations).
- Tests that load the real shipped `content/` through the real loaders (`Shipped*ContentDecodesTest`, `StageContentsTest`, `SkillVisualContentTest`, ...), i18n key coverage over the real files, pack validation of the real built resource pack.
- `tools/architecture-test` Konsist rules (architecture enforcement, ADR number uniqueness, i18n parity).

When unsure: does it boot or load real components or real files end-to-end? Keep : delete.

## Forbidden

- A test class that builds one object with fakes/mocks and asserts on it (use a game-sim scenario instead).
- Generator math / determinism / parser / layout-math tests in `tools/*`.

## Guard

`tools/architecture-test` `TestPolicyTest` fails the build if `plugin/*/src/test/` contains a test class that is not `*IT`, not `Shipped*Test`, and not listed in `tools/architecture-test/src/test/resources/konsist-allowlist/plugin-tests.txt`. Helper files are allowed there only under `harness/`.
