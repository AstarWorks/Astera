- 系統が一致していても、出典が [題のみ]・[二次] 中心なら本文に「低信頼」と書く。

## 1. 軸 (Axes)

素材から導いた 7 軸。1 つのパターンは 1 つの主軸に置き、他軸は「関連」に書く。

| 軸 | 問い | パターン |
|---|---|---|
| 時間 (T) | いつ・どの長さで何を出すか。溜め → 発動 → 命中 → 余韻 | T1-T7 |
| 空間・構図 (S) | どこに置くか。芯・外周・地面・視界・画面の前景 | S1-S6 |
| 役割分担 (R) | どの素材に何を任せるか。粒 / sprite / 3D 実体 / 板 | R1-R5 |
| 色と明暗 (C) | 何色で、どの明度で、どの背景に勝つか | C1-C4 |
| 密度と予算 (D) | どれだけ出し、何を削るか。重要度との連動 | D1-D3 |
| 動き (M) | 軌道・補間・誇張。形そのものでなく動かし方 | M1-M4 |
| 感覚の束ね (F) | 音・画面・停止など、絵以外のチャンネルとの同期 | F1-F3 |

軸の補足:

- 時間軸は資料の大半を束ねる縦糸 (桜井 / 業界 / RD / 失敗事例のどれもが「いつ」を語る)。他の軸は「その時刻に何を足すか」の選択。
- 役割分担軸は Minecraft 固有。Display (面・意味) と粒 (勢い・量) と実体 (質量) の分担が、他ゲームの資料には無い。
- 密度軸は他軸の上位制約 (D1 が決めた格で、他のパターンを何個重ねてよいかが決まる)。

## 2. パターンカタログ

書式: **名前 (EN)** / 一行 / なぜ効く / Minecraft レシピ / 根拠 / Astera / アンチパターン。

### 時間 (T)

#### T1. 溜めと一閃 (Hold and Snap)
- 一行: 構えは瞬時に極端に取り、ピークで保持し、発動は 1 tick で切り替える。
- なぜ効く: 保持が長いほど切替の速さが際立つ。補間を均一にすると全部がもっさりする。
- レシピ: rig `swing` の keyframe を 溜め = 補間 0 (保持) / 発生 = 1t スナップ / 余韻 = 長い補間 に分け、区間ごとに ease を変える。溜め中は P-S4 (収束) で「何かが集まる」を足す。
- 根拠 (強い根拠): SK §2 [一次] + SK §1 (構えは瞬時に) + IND §2 (Xrd・Spider-Verse) + RD-9 + 正本 §0.5 チェックリスト 6。
- Astera: 部分 (rig の ease と keyframe で書ける。`windup` 構文は未対応)。
- アンチ: G-8 (溜めが読めない), G-9 (全要素同じ ease), G-23 (尺が重要度に合わない)。

#### T2. 前倒しと長い尾 (Front-loaded Decay)
- 一行: 主動作は寿命の最初の 1/4 で終え、残りを減衰する余韻に回す。
- なぜ効く: ピークが早いと「当たった」が先に読め、尾が質量を語る。
- レシピ: 命中のピークを 1-2t、減衰 3-4t (IND §3 [二次])。`alpha_over_life` / `size_over_life` は線形にせず、`start_tick`/`end_tick` で要素ごとに終了をずらす。
- 根拠 (強い根拠): 正本 §0.5 ([二次]) + SK §2 (フォロースルーは行きより長く) [一次] + E3-12 (爆発より小さく疎な粒が後に残る) + IND §3。
- Astera: 対応 (skill / vfx 側の運用)。
- アンチ: G-22 (寿命が長く濁る), G-14 (フラッシュが長く「スタン」に見える)。

#### T3. 命中は同じ tick (Hit-Sync)
- 一行: 命中の絵・音・停止は damage と同じ tick に置く。振っただけでは二次演出を出さない。
- なぜ効く: 因果が一致して手応えになる。外れたら出さないことで「当たった」の情報価値が保たれる。
- レシピ: `phases.hit` / `dash_strike.on_hit` / `hit_entity` 側に spawn。命中 tick に短く鋭い transient の音 (IND §1 の音タイミング [二次] は立ち上がり 10ms 未満を推奨、低音は命中の 1-2t 前) を `delay_ticks` で合わせる。刃の通過 tick = damage tick。
- 根拠 (強い根拠): 正本 §0.5 + IND §1・§2 (Capcom [一次]: 着弾でだけ二次) + SK §1 (攻撃判定を常に意識 [題のみ]) + E3-6 (命中点の扇)。
- Astera: 対応。
- アンチ: G-25 (当たりが見えない), G-27 (刃と判定がずれる)。

#### T4. 重さの階段 (Weight Ladder)
- 一行: ヒットストップは強さの階層で長さを変え、全ヒット同一にしない。上限を設ける。
- なぜ効く: 止める長さそのものが「重さ」の語彙になる。多人数戦では短くして止まった相手を第三者が殴れないようにする。
- レシピ: `hit_stop` の `ticks` を 軽 1-2 / 重 3-4 / 決め 6 を目安 [推論]。多段は各 beat で小さく足し、最後だけ大きく。vfx 側は同 tick に `freeze`。
- 根拠 (強い根拠): SK §3 (vol.490 [二次]) + 正本 §0.5 + IND §1 + T-22 (既製 MOD の同時処理)。
- Astera: 部分 (`hit_stop` あり。停止中の揺れの縮み・術者のスロー・被弾モーションの馴染ませは未対応)。
- アンチ: G-11 (23/26 が 2 tick), D-A8 (固定が長すぎる)。

#### T5. 満ちる予兆 (Filling Telegraph)
- 一行: 範囲の外縁は実寸で即出し、内側の塗りを着弾へ向けて広げ、「どこに・いつ」を 1 つの図形で読ませる。
- なぜ効く: 範囲と時間が同じ図形に載る。PvP で公平。
- レシピ: リング 2 枚 (外 = 即時で全径、内 = 着弾までかけて全径)。雛形 `bastion-s3-telegraph`。立ち上がり 2.5-4t・保持 5-11t (IND §3 [二次])。判定半径 = 見た目半径。危険色は敵予兆専用に予約。
- 根拠 (強い根拠): RD-2 + 正本 §0.5 (予兆の形 = 判定の形) [二次] + IND §3 + SK §1 (判定のあるものを強調 [題のみ])。
- Astera: 部分 (リング 2 枚で書ける。専用要素・チーム色・`lane` は未対応)。
- アンチ: G-2 (予兆を見逃す), D-A5 (外輪が判定と無関係)。

#### T6. 爆発の拍 (Burst Beats)
- 一行: 閃光 → 爆炎 → 煙へバトン → 収束、の順に拍を分け、最後に小さく疎な粒を残す。
- なぜ効く: 拍の切れ目がリズムになり、消え際が「パッ」と締まる。
- レシピ: 閃光 (爆発範囲より大きく、黒も混ぜる、1-2t) → 爆炎 (不透明の芯) → 暗い煙 → 余韻の粒 (別要素・長寿命・粒は小さく疎)。`start_tick`/`end_tick` で拍を分ける。判定は爆炎の間ずっとは出さない。
- 根拠 (強い根拠): 正本 §0 の 3 (桜井の回) + E3-12 (3 拍) + E3-8 (球殻とリング) + 正本 §4 (1 ビートの重ね方)。E3 の「3 拍」と正本の「4 段」の差は §4 に記載。
- Astera: 対応。
- アンチ: D-A7 (真っ白), G-20 (白飛び), G-4 (画面全体が埋まる)。

#### T7. ずらし発火 (Stagger)
- 一行: 全部を同 tick に出さず、1-2t ずつずらして変化量を分散する。
- なぜ効く: 同時発生は一塊に潰れる。ずらすと視線が追えて密度が増して見える。
- レシピ: `delay_ticks` で周囲の発光・粒・sprite を 1-2t 遅らせる。重ならない位置に置く。
- 根拠 (強い根拠): 正本 §0 の 4 (桜井) + IND §3 (シャドバ WB [一次]) + E3-5 (点を 1-2t ずつずらす, E3-7 の色層も同様)。
- Astera: 対応。
- アンチ: G-21 (同時に全部光る), D-A1 (毎 tick 大量)。

### 空間・構図 (S)

#### S1. 芯・縁・地面の三層 (Core, Rim, Ground)
- 一行: 脅威の位置に不透明の芯、半透明の外周、そして必ず地面側の要素を置く。
- なぜ効く: 芯が視線を止め、外周が流し、地面が空間のアンカーになる。
- レシピ: 芯 = 不透明 block/quad、外周 = 半透明 quad、地面 = ring / `block_crumble` / 飛散。層は 芯 / 閃光 / 火花 / 煙 / 地面 / (決め技のみ) 画面。
- 根拠 (強い根拠): 正本 checklist 7 + IND §3 (Relink・Cygames [一次]: 空間アンカー) + E3-8 (足元のリング) + SK §1 (重さは接地面の反応で語る [題のみ])。
- Astera: 対応。
- アンチ: G-17 (情報が消える), G-26 (何も残らず軽い)。

#### S2. 接地反応 (Ground Reaction)
- 一行: 見えない質量を、地面の欠け・粉塵・ひび・焦げ跡で語り、短時間残す。
- なぜ効く: 軽い絵でも地面が反応すると重く感じる。残ることで「起きた」が持続する。
- レシピ: `block_crumble` 粒子、`set_block` (revert あり) で 20-60t 残す、地面すれすれの ring (+0.1)。背景ブロックが一瞬揺れる / 欠ける。
- 根拠 (強い根拠): IND §1 (Vlambeer の永続性 [二次]) + IND §3 (Capcom [一次]: 背景が反応) + E3-8, E3-15, E3-23 (地面側の要素が多い) + SK §1 [題のみ]。
- Astera: 部分 (`set_block` / `block_crumble`)。
- アンチ: G-26。

#### S3. 球殻とリングの幾何 (Shell and Ring)
- 一行: 形は球殻・ドーム・輪・弧など単純な幾何で組む。
- なぜ効く: 幾何は遠くから一目で読め、重なっても濁りにくい。
- レシピ: formation (`sphere` / `circle` / `arc` / `ring`)。足元のリングは別要素で拡大。放射状の板は各板を放射方向に回す。
- 根拠 (強い根拠): E3-8, E3-13, E3-20 + RD-5/6 (十字板・輪) + 正本 §2 (部品選び表の formation)。
- Astera: 対応。
- アンチ: G-10 (放射板が中心を向かない)。

#### S4. 収束と拡散 (Converge and Release)
- 一行: 溜めは粒が中心へ集まる、解放は逆に広がる。対で使う。
- なぜ効く: 「集まる」は見た目だけで溜めと読める。
- レシピ: `Particle.Trail` で中心へ、または spread を小さくしていく。解放で逆に広げる。
- 根拠 (強い根拠): RD-13 + G-8 の修正案 (IND 系ブログ) + E3-20 (中心に粒が集まる)。3 系統だが全て [二次] 以下、低信頼。
- Astera: 対応。
- アンチ: G-8。

#### S5. 一人称の視界設計 (First-Person Frame)
- 一行: 一人称の狭い視野を前提に、視野中央を塞がず、武器や前景を構図に入れる。
- なぜ効く: Minecraft は一人称が基本。視野 ±30° の外は無いのと同じ。
- レシピ: 斜め配置、術者側は薄く、eye view で pitch を下げて撮る。武器 rig を視界の下方に張り出す (E3)。per-player 表示は未対応。
- 根拠 (複数): SK §1 (世界の窓 [題のみ]) + 正本 §3 + E3-22 (一人称で武器が視界に入る) + M-16 (一般論・未確認)。低信頼。
- Astera: 部分 (一人称の見えの検証手順は未整備)。
- アンチ: M-16, M-1 (視線を下げると消える)。⚠ §4 参照 (正本 §0 末尾の ItemDisplay 方針との緊張)。

#### S6. 前景の幕 (Foreground Veil)
- 一行: カメラ近傍に大きな平面片や柔らかい煙塊を置き、他の粒が奥に見える階層を作る。
- なぜ効く: 前景があると奥行きができ、粒が「向こう側」に見える。
- レシピ: 近接 quad / sprite を大スケールで置き、`size_over_life` で緩く拡大しつつフェード。
- 根拠 (単独): E3-3, E3-25, E3-2。
- Astera: 部分 (`screen_flash` は全面色のみで形を持てない。近接 Display で近似、display 上限 60/cast を食う)。
- アンチ: G-4 (単発の面積上限)。⚠ §4 参照。

### 役割分担 (R)

#### R1. 面は意味、粒は勢い (Sign and Spray)
- 一行: 形と意味を Display (sprite / 板) に、動きと量を vanilla 粒に任せる。
- なぜ効く: 絵は粒より解像度が高く、粒は絵より安く大量に動かせる。役割が違う素材を一つに混ぜない。
- レシピ: sprite / block を 1 枚 + `emit` (sphere / line) で粒を併用。
- 根拠 (強い根拠): 正本 §0 冒頭 + E3 原則 9 / E3-4 / E3-18 + RD-1 + T-28。
- Astera: 対応。
- アンチ: Display だけ、または粒だけで作る (正本が禁止)。

#### R2. 絵で見せる sprite (Sprite as Spark)
- 一行: 数フレームのドット絵を 1 エンティティ(TextDisplay + glyph)で再生し、粒の解像度を超える質感を出す。
- なぜ効く: 1 sprite ≒ 数百粒より軽いことが多く、フレーム差し替えで「絵の動き」が出る。
- レシピ: `type: sprite` (`frame_ticks` 1-2, `loop`, `color`)。黒背景でも輪郭が潰れない部品セットから始める。
- 根拠 (強い根拠): RD-1 + E3-1 + IND §4 (Xrd のヒット = 2D の連続切替) + T-27/T-28。
- Astera: 対応 (ADR-0239)。標準セットの不足は §5 の欠落。
- アンチ: binary alpha で薄い絵が出ない (M-9)。

#### R3. スケール差 (Scale Contrast)
- 一行: 同じ部品を豆粒から画面を埋める大きさまで振る。種類を増やすより効く。
- なぜ効く: 比率の差が奥行きと迫力になる。
- レシピ: Display scale を数十倍に振り、`size_over_life` で伸縮。重要度に比例させる。
- 根拠 (複数): E3-2 + 正本 §0.5 (重要度 = 大きさ) + SK §1 (正しい大きさ感 [検索要約のみ])。
- Astera: 部分 (画面占有サイズの実測なし)。
- アンチ: D-A7 (scale 90 は白一色)。⚠ §4 参照。

#### R4. 一板多粒 (Many in One)
- 一行: 1 枚の板に複数の粒を描き、エンティティ数を節約する。
- なぜ効く: 数百エンティティより 1 枚の glyph が軽い。
- レシピ: TextDisplay 1 体に `✦ · ✧ ·` を並べる / sprite シート。
- 根拠 (強い根拠): 正本 §0 の 4 + RD-1 + E3-1 + IND §3 (CC2 の高速回転はテクスチャで)。
- Astera: 対応。
- アンチ: D-A1, D-A2 (魔法陣を粒で描き続ける)。

#### R5. 実体を振る (Swing the Real Thing)
- 一行: 大きな実体を手元を軸に実際に振り、粒は補助に回す。
- なぜ効く: 実体は見えているだけで質量と軌道の情報を持つ。
- レシピ: rig (pivot = translation / swing = left / 向き補正 = right)。風切りは刃の通過に沿う扇面。削除は更新の次 tick。
- 根拠 (強い根拠): RD-8 + 正本 §7 + T-6 + E3-22。
- Astera: 対応。
- アンチ: M-3, M-6 (補間が飛ぶ・逆回り)。

### 色と明暗 (C)

> ピクセル作法 (帯状の色ランプ・熱の予算・texel 密度) は [`pixel-vfx-craft.md`](pixel-vfx-craft.md) の P1 / P5 / P6。

#### C1. 暗を混ぜる (Dark in Light)
- 一行: 明るい効果には暗い縁か暗い粒を必ず混ぜる。白黒で見て主役が残るか確かめる。
- なぜ効く: 加算だけの発光は明るい背景で消える。明度差が輪郭を作る。
- レシピ: 黒 / 暗色の dark rim、暗い粒、暗い煙 + 赤橙の火。レビューは `ffmpeg -vf format=gray`。
- 根拠 (強い根拠): 正本 §0 の 1/2 (桜井) + E3-9, E3-19 + G-6/M-17 (blog 報告) + SK §1 (白黒で確認 [題のみ])。
- Astera: 対応。
- アンチ: G-6 (加算だけ), G-3 (色だけで区別)。

#### C2. 二色の層 (Two-Tone Stack)
- 一行: 主色と差し色の 2 層をずらして重ね、色は 3-4 以内、支配色を 1 つに。
- なぜ効く: 単色より深みが出て、混色より濁らない。
- レシピ: 同じ形を色違いで 1-2t・数 % ずらす (`color_over_life`、sprite の `color`)。
- 根拠 (強い根拠): E3-7, E3-19 + 正本 checklist 5 + IND §3 (CC2: 4 階調以内 [一次])。
- Astera: 対応。
- アンチ: G-1 (全部が同じピークを奪い合う)。

#### C3. 硬い芯・柔らかい裾 (Hard Core, Soft Skirt)
- 一行: ハードエッジは視線を止め、ソフトエッジは流す。明度は主役に集める。
- なぜ効く: 視線誘導と空間感が同時に得られる。
- レシピ: 芯 = 不透明、周辺 = 半透明 quad。煙の縁の段差は残して柔らかく(E3)。
- 根拠 (強い根拠): IND §3 (Relink・Cygames [一次]) + 正本 §0 の 1 + E3-3 + G-17。
- Astera: 対応。
- アンチ: G-17。

#### C4. 舞台別配色 (Stage-Aware Palette)
- 一行: 同じ技でも背景の明暗で配色を変える。
- なぜ効く: 明るい背景では白が埋もれ、暗い背景では白が主役になる。
- レシピ: 明るい場面は彩度の高い暗色を混ぜる。暗い場面は白・金を主役に。
- 根拠 (単独): E3-24 (隣接: E3-19, G-6)。
- Astera: 未対応 (ステージ別の配色切替の仕組みが無い)。
- アンチ: M-17。

### 密度と予算 (D)

#### D1. 重要度の配給 (Importance Ration)
- 一行: 技の重要度 1-10 を先に決め、大きさ・明るさ・長さ・音の層・Display 数をそれに合わせる。主役は 1 つ。
- なぜ効く: 全部が派手だと何も読めない。派手さは配給制。
- レシピ: 重要度 → 格の表 (RD §3.2 / `next-improvements.md` 末尾) に当てはめる。尺を伸ばしたら `cooldown_ticks` / `ego_cost` も上げる。
- 根拠 (強い根拠): 正本 checklist 1/4 + IND §3 (Diablo・LoL・CC2) + RD §3 + SK §1 (効果音も重要度で)。
- Astera: 部分 (層タグ・`lane` は未対応)。
- アンチ: G-1, G-15, D-A6, D-A7。

#### D2. 少なく・短く・ずらす (Few, Short, Staggered)
- 一行: 粒は少なく賢く、寿命は短く、位置を重ねない。
- なぜ効く: 重なりは無駄で、数は濁りと負荷を呼ぶ。
- レシピ: 出現 tick をずらす、白と黒を混ぜる、詠唱中は 4-10t のパルス + Display 1 個。煌めきは大小混在で数を絞る (E3-14)。
- 根拠 (強い根拠): 正本 §0 の 4 + G-22 + E3-14 + RD §2 (詠唱の粒を毎 tick 出し続けない)。
- Astera: 対応。
- アンチ: D-A1, D-A2, G-12 (コンボの全フレームに粒子)。

#### D3. 三層で削る (Cull from the Bottom)
- 一行: メイン / サブ / 賑やかしの 3 層に分け、負荷や混雑では賑やかしから削る。
- なぜ効く: 削る順序が決まっていれば、読みやすさを保ったまま予算に収まる。
- レシピ: 要素に層を付け、寿命を 主 > 副 > 賑やかし に。最も騒がしい戦闘を固定レビューシーンにする。
- 根拠 (強い根拠): IND §3 (CC2 [一次]) + G-15, G-24 (Capcom [一次]: 最初から予算) + 正本 §5。
- Astera: 部分 (層はチェックリストのみ。タグ・品質プロファイルは未対応)。
- アンチ: G-5, G-24。

### 動き (M)

#### M1. 非線形の緩急 (Non-linear Ease)
- 一行: 線形を使わず、要素ごとに別の ease・別の速度で動かす。頂点で 1-2t 止める。
- なぜ効く: 非一様な動きは「生きて」見える。
- レシピ: rig / 粒の `*_over_life` を要素ごとに変える。補間 2t 保持を基本に決めの瞬間だけ 1t (twos/ones)。
- 根拠 (強い根拠): 正本 checklist 6 + SK §2 + IND §2 (Xrd・Spider-Verse) + E3-5。
- Astera: 対応。
- アンチ: G-9。

#### M2. やり過ぎてちょうどよい誇張 (Exaggerate)
- 一行: 実際の角度より大きく引き、大きく振る。補間は動きを痩せさせる。
- なぜ効く: 3D と補間は躍動感を失う。誇張を足して初めて同じ強さに見える。
- レシピ: rig の `rest` / `swing` を 110° → -190° のように大きく。
- 根拠 (複数): SK §1 (やり過ぎて [二次]) + SK §2 [一次] + IND §2 (Xrd)。
- Astera: 対応 (rig)。slerp の逆回り制約あり (M-6)。
- アンチ: 動きに攻撃が負ける (SK §2)。

#### M3. 点線の軌跡と太い一弧 (Dotted Trail, Fat Arc)
- 一行: 軌跡は間隔を空けた点列を基本に、太い一本の弧を混ぜる。高速の振りには 1-2t だけ歪む破片 (smear) を挟む。
- なぜ効く: 実線は重く、点線は速度と軽さを出す。太い弧は一撃の質量を示す。smear は高速で空く刃の間を埋める。
- レシピ: 経路を等間隔サンプルし 1 点ずつ 1-2t ずらして出す (`trail`, `shape: arc/line`, `rig_path`)。太い弧は arc / ring を短時間スイープ。
- 根拠: 軌跡の存在・smear は強い根拠 (正本 §0.5 風切りの欠け + IND §2 StretchBlur [一次] + IND §4 Spider-Verse)。**点線という形は単独** (E3-5, E3-21)。
- Astera: 部分 (`trail` は近接で四角に見える注意。点列の標準部品が無い)。
- アンチ: 風切りの間延び・間が空く筋 (正本 §0 の 5)。⚠ §4 参照。

#### M4. 公転と螺旋と渦 (Orbit, Helix, Swirl)
- 一行: 対象の周りを回る輪、軸に沿う螺旋、接線方向の渦で「持続」と「力の場」を見せる。
- なぜ効く: 回転は静止物にも動きを与え、持続技や溜めの間を持たせる。
- レシピ: `follow: true` の circle + rotate keyframe、`shape: helix/spiral`、emit `direction: tangent`。輪ごとに位相をずらす。
- 根拠 (強い根拠): E3-13, E3-20 + RD-6, RD-7 + T-18。
- Astera: 部分 (包絡の指定は未確認)。
- アンチ: D-A1。

### 感覚の束ね (F)

#### F1. 音の層とピッチの弧 (Layered Pitch Arc)
- 一行: 同じ音を高低 2 ピッチで重ね、チャージは上昇・減衰は下降、頂点で一瞬の無音を作ってから一撃。
- なぜ効く: 絵より安く期待を作る。重要度を音量・層数でも表す。
- レシピ: `play_sound` を `delay_ticks` 違いで並べ、pitch は 0.5-2.0 に収める。ヒット音は短い transient。
- 根拠 (強い根拠): RD-4 + IND §1 (音のタイミング [二次]) + SK §1 (重要度で音量・アタック強め [題のみ]) + T-33。低信頼 (一次なし)。
- Astera: 部分 (弧の宣言構文、`stopsound` 相当は未対応)。
- アンチ: D-A3 (全員に大音量), D-A6 (同じ爆発音の多用), D-A11 (pitch clamp)。

#### F2. 画面パンチ (Screen Punch)
- 一行: 命中の瞬間に、フラッシュ・揺れ・衝撃枠を短く重ねる。決め技限定。
- なぜ効く: 画面全体のアピールは手応えを大きく変える。ただし連打と過剰は酔いと不快を生む。
- レシピ: `screen_flash` の連鎖 (white 1t → gold_burst 2t → speed 系 2t) を `delay_ticks` で 1t ずつずらす。`camera_shake` は単発を決めの 1 tick に。白の間に暗転を挟む。対象は術者と被弾者のみ。
- 根拠 (強い根拠): 正本 §0 の 3 (桜井) + SK §1 (画面振動・フラッシング) + IND §3 (シャドバ・MHA [一次]) + IND §4 (Xrd)。
- Astera: 部分 (`camera_shake` は単発の kick のみ。減衰する揺れは未対応)。
- アンチ: G-13 (揺れの多重), G-14, G-4, G-29。

#### F3. 強度ダイヤル (Intensity Dial)
- 一行: 揺れ・フラッシュ・粒量をプレイヤーが調整でき、混雑した戦闘でも読めるようにする。
- なぜ効く: 光過敏・酔い・性能差に対応できる。強すぎる停止は操作を邪魔する。
- レシピ: viewer ごとに Display 数・粒量・揺れを間引く。
- 根拠 (複数): SK §1 (画面振動・フラッシング [題のみ]) + IND §1 (MH Wilds [二次]) + T-26 (Wynncraft のプレイヤー製 MOD)。低信頼。
- Astera: 未対応。
- アンチ: G-29, M-11 (粒子設定で消える)。

## 4. E3 が新しく足したもの・古い資料との食い違い

### 4.1 E3 が足したもの
- **点線の軌跡 + 太い一弧** (M3): 従来は「刃の通過に張る扇面」が主流 (桜井・正本) だった。点列という別の語彙が増えた。
- **スケール差** (R3) と **前景の幕** (S6): 従来は「重要度 = 大きさ」止まり。同じ部品を極端に振る、画面近傍に層を置く、という構図の方法が足された。
- **舞台別配色** (C4): 従来の「暗を混ぜる」(C1) を、背景に応じて配色ごと変える話に拡張。
- **二色の層** (C2): 従来の「3-4 色」に、層をずらして重ねる作り方を足した。
- **面 = 意味、粒 = 勢い** (R1) を明文化。従来は「形と面は Display、動きと粒立ちは粒子」(正本) の一行のみ。
- **3 拍の爆発 + 余韻の疎な粒** (T6/T2) と **一人称の武器** (S5)。
- **スプライトのドット絵セット** (R2): RD の「スプライトを粒に」を、黒背景で単体成立する部品セットという制作ルールに具体化した。

### 4.2 食い違い・緊張 (⚠ 解決せず、旗のみ)
| 項目 | E3 側 | 規則側 | 扱い |
|---|---|---|---|

## 6. 使い方

1. skill の重要度 (D1) を決め、§3 の近いレシピから始める。
2. T 軸 (いつ) → S/R 軸 (どこに・何で) → C 軸 (色) → F 軸 (音と画面) の順に足す。足す前に D2/D3 で削る。
3. 失敗事例 ([`failure-patterns.md`](failure-patterns.md)) をアンチの欄から逆引きしてレビューする。
4. 新しい技法を資料集に足すときは、この文書に既存パターンがあるか確認し、あれば根拠欄に出典 ID を足す。無ければ「単独」として足す。
