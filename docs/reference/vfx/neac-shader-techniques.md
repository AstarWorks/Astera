## A. 地形・画面全体のシェーダー効果

### NA-1 魚眼・湾曲した床
- [観察] 平らなアリーナの床と壁が、画面の周縁に向けて湾曲して見える。動いている間も常時かかる。
- [推論] 地形頂点を視点距離で曲げる処理 (terrain の頂点段で view 空間の位置をずらす) か、射影 (FOV 側) の歪み。どちらも自前でシェーダーを置く前提。
- Astera: (b)。`terrain.vsh` へのパッチ + 効果の ON/OFF を伝える経路が要る。FOV 経由なら ProjMat が変わるので全ジオメトリが歪み、粒子・ディスプレイも一緒に曲がる (一貫するが、一人称の手元も歪む)。マーカー経路が無いと全プレイヤー・全ブロックにかかる。
- 衝突リスク: 頂点を動かすので、ライトの値などのマーカーでは**狙ったブロックだけ**に絞れない (SKL-03 の教訓: 自然ライト 0-15 は偽造可能)。
- 出典: https://x.com/EMagipi/status/2115235656280821981

### NA-2 壁をのぼる青い波状のスキャン帯
- [観察] 青い波打つ帯が床から壁へ這い上がる。帯は地形に張り付き、ブロックの面に沿って曲がる。
- [推論] terrain の fragment 段で、ワールド座標 (または高さ) と GameTime から帯を作って色を足す。Display を地形に貼る方法では面に沿って曲がらないので、シェーダー側と見るのが自然。
- Astera: (b)。`terrain.fsh` へのパッチ。GameTime は `globals.glsl` を include するシェーダーでのみ使える。帯の位置・色をスキルごとに渡す経路 (NA-3 と同じ) が要る。
- 出典: https://x.com/EMagipi/status/2115235656280821981

### NA-3 床が青灰色の場に沈む
- [観察] アリーナ床全体 (局所のリングではない) がスキル中に青灰色へ暗くなる。
- [推論] terrain の色またはライトマップを全体に重ねる。ライトマップ UBO (`LightmapInfo`) を Darkness / Night Vision / ボスバーの暗転で動かす方法なら、パックのシェーダーだけで済み、サーバーは効果 (ポーション) を付けるだけで発火できる。
- Astera: (b)、ただし最小コスト版は効果ポーション + `lightmap.fsh` パッチ。プレイヤー単位でかかる (他人には出ない) のは利点。エンティティ・粒子も同じライトマップを使うので暗くなる範囲が広い。
- 衝突リスク: 本物の暗闇・夜間視・ボスバーと区別できない (同じ値)。「効果の強さ + 継続時間」の組を決めて予約する必要がある。
- 出典: https://x.com/EMagipi/status/2115235656280821981

### NA-8 テクスチャを歪める地形 (橙色の地面)
- [観察] 橙色の地面・壁のテクスチャが、ブロックごとではなく大きく拡大・歪んだ模様に見える動画がある。画面中央に文字 (Ready / STAGE SELECT 等) が重なる。
- [推論] terrain の UV をワールド座標由来に置き換える (ブロック境界を無視する) 処理、または特定ブロックのテクスチャ差し替え。
- Astera: (b) だが優先度は低い。見た目の用途がスキル VFX から遠い (ステージ演出)。
- 出典: https://x.com/NeAc_/status/1871115193180463177

## B. 地面・空中の演出部品

### NA-4 地面のホログラム輪と周回する点
- [観察] 床に水色の細い輪が複数並び、輪の周りを小さな点が回る。ほぼ水平に寝ている。
- [推論] 水平に寝かせた Display (sprite / TextDisplay) の輪 + 周回する粒子または小 Display。
- Astera: (a)。`display kind: sprite` を `rotate` で水平に倒し、`orbit` で点を回す (ADR-0303 section 2.1 / 3)。輪の絵は `content/sprites/` に置く。シェーダーは不要。
- 出典: https://x.com/EMagipi/status/2115235656280821981

### NA-5 細い垂直の光線と斜めの筋
- [観察] 天井方向へ延びる細い垂直線と、斜めに走る短い筋が複数。
- [推論] 細長く引き伸ばした block / text Display か粒子の筋 (end_rod 等)。
- Astera: (a)。thin display の `scale` と ribbon / 粒子で足りる。加算ブレンドが無い点は既知のギャップ (`patterns.md` 5 の 7 番)。
- 出典: https://x.com/EMagipi/status/2115235656280821981

### NA-9 緑の発光球とウィンドウ状パネル
- [観察] 緑に光る球体の中にパネル状の窓が出る画面 (スキル発動直後のような構図)。
- [推論] 球体は発光 (brightness 15/15) の item / block Display、パネルは TextDisplay の背景。
- Astera: (a)。`brightness` と `text` の `background` で表現できる。球の輪郭のにじみは (b) (SKL-07 の発光試作の範囲)。
- 出典: https://x.com/NeAc_/status/2114333363960217684

## C. 一人称・画面転換

### NA-6 一人称の手元の黒い球
- [観察] 一人称視点で、手元に黒い球が浮かぶ。
- [推論] 手に持つ item の model (item_display ではなく手持ちモデルの差し替え) か、プレイヤー追従の Display。
- Astera: (a)。手持ち item の model 差し替えは `content/items/` の仕事で、武器マーカー (ADR-0275: brightness (240,224) + 定数 tint (254,254,254)) は触らない。視界に入る大きさは `patterns.md` の S5 参照。
- 出典: https://x.com/EMagipi/status/2115235656280821981

### NA-7 終端の暗転
- [観察] 動画の終わりで黒へフェードし、その後ポーズメニューが出る。
- [推論] 暗転は画面全体の overlay (title 表示 / 全面 text / ポストエフェクト) のいずれか。
- Astera: (a)。skill の `screen_flash` (全面色) で足りる。形のある前景は既知のギャップ (`patterns.md` 5 の 6 番)。
- 出典: https://x.com/EMagipi/status/2115235656280821981

## D. GUI 風・空間配置

### NA-10 湾曲したドーム内に浮かぶパネル群
- [観察] 魚眼様に歪んだ広い空間の中、プレイヤーの周囲に半透明のパネルが円弧状に並ぶ。「ゲーム開始」等の文字付き。

## 実現性 (26.3 の core shader とリソースパック)

- **届くもの**: `core/` の terrain / block / entity / item / particle / text / sky / lightmap / world_border など、パックが同名で置き換えられる core shader。Astera は元の GLSL を再配布せず、ビルド時にクライアント jar から取り出して `@@ before|after|replace: <anchor>` で差し込む (`tools/resource-pack/.../ShaderPatch.kt`, `ResourcePackBuilder.kt`, `VanillaShaders.kt`)。既存の差し込み: `content/shader-patches/core/{entity,item}.{vsh,fsh}.patch` (リグのマーカー復号、武器の暗部持ち上げ)。
- **スキルごとのデータが届く経路** (既存の 2 つ): (1) エンティティのリグマーカー = ブロック光 14 + 空光ペイロード + 巻き方向の確認 (ADR-0298)。(2) 武器の item マーカー (ADR-0275)。**ライト値のみのマーカーは自然ライト 0-15 で偽造される**ので、巻き方向や定数 tint との組み合わせが前提 (SKL-03 の教訓)。
- **地形効果をサーバーから発火する方法** ([推論]。投稿には書かれていない): 地形シェーダーは頂点に載るデータが固定で、スキル固有の値を直接運べない。そのため uniform の「乗っ取り」になる。(1) ライトマップ UBO を動かす Darkness / Night Vision / ボスバー暗転。(2) FOV 変更による ProjMat。(3) フォグ (Blindness)。(4) GameTime は `globals.glsl` を include するシェーダーでのみ使え、`particle.vsh` では使えない。いずれも**プレイヤー単位**の状態で、ポーションなど通常機能で付けられる反面、本物の効果と区別がつかない。
- **届かないもの (c)**: クライアント側の post_effect を自由に呼ぶこと (26.3 でパックがどこまで許すかは、キャッシュ済みファイルからは未確認)、サーバーからの任意の uniform 送信、ブロック単位の任意データ。

## (b) 候補の優先順位 (`next-improvements.md` に転記)

1. NA-3 の最小版: 効果ポーションで `lightmap.fsh` を動かし、スキル中に床・空を青灰色へ寄せる。最も安い。
2. NA-2: `terrain.fsh` の帯 (高さ + GameTime)。NA-3 と同じ発火経路を共有できるなら次に安い。
3. NA-1: 頂点湾曲 / FOV。影響が全ジオメトリで、一人称の手元も歪むため検証が重い。
4. NA-8: UV の置き換え。スキル VFX から遠いので最後。
