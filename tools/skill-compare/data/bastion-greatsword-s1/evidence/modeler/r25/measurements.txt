## Cause (no transform bug)
- 26.3 jar: Lighting LEVEL = fixed world directions; PoseStack normal = inverse-transpose + normalize for scaled display
  transforms, camera rotation lives in ModelViewMat, so the normal IS world-space and correct for every rig part.
- keys.py (rig euler -> world normal per face -> vanilla) reproduces the director's numbers from geometry alone:
  side key 0 (held) broad face n=(1,0,0) -> 0.50 (220 x 0.50 = 110, measured 108); key 2 n.y +0.38 -> 0.77; key 3 (shown t4)
  n.y +0.84 -> 1.00 = iron 220 / quartz 231 (measured 230). The swing turns the blade face to the SKY while the side camera
  still sees it: vanilla's up side (1.0) was untouched by the r24 rule, which only lifted down faces.
- Compare coil (keys 3-4, t4-5): the camera sees the +X EDGE (vis 0.60-0.93), i.e. the polished_blackstone rims (texture luma
  50) and tip parts; 50 x 0.65 = 33 = measured. Texture, not light: no lighting rule can lift it above ~50.
- Same rule for the held item: its own spread across azimuth/pose is the same 0.40-1.0, just not exercised by a static hold.

## Fix (content/shader-patches/core/item.{vsh,fsh}.patch, same two markers as ADR-0275)
- vsh: shade = 0.65 + 0.35 * (vanilla - 0.65): 0.57 (down) .. 0.77 (up); side faces 0.56-0.68. Replaces the r24 underside lift.
- fsh: marked faces lift dark texels on luma, hue kept: y' = y + 0.3 (1 - y)^2 (blackstone 50 -> 100, deepslate 73 -> 112,
  iron/gold/quartz +1-3). A per-channel first try greyed the gold guard and gem (rejected; capture 1).
- GUI (orthographic ProjMat) keeps vanilla shading; held marker colour still reset to white there.
